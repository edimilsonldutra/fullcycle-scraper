## Resumo da aula

Skills não são um adorno para dizer que um projeto usa IA; elas são um mecanismo de organização do conhecimento operacional que o agente não precisa carregar o tempo todo na janela de contexto. Retomando CLAUDE.md e AGENTS.md, esses arquivos continuam úteis para instruções gerais e comportamento base, mas tudo o que for colocado neles entra logo no início da sessão. Quando instruções especializadas ficam fora desse carregamento inicial e são ativadas apenas quando necessário, o uso de contexto se torna mais eficiente e a interação tende a ganhar assertividade.

Um projeto sem skills pode desperdiçar tokens e, ao mesmo tempo, reduzir a qualidade das respostas da IA durante o desenvolvimento. O problema não é apenas custo: sem segmentação por capacidade, o agente recebe menos orientação específica para tarefas recorrentes ou especializadas do domínio do projeto. Isso aumenta a chance de respostas genéricas, decisões menos precisas e menor aproveitamento da ferramenta no fluxo de trabalho.

A existência de suporte a skills nas ferramentas atuais não significa criar skills artificialmente para qualquer detalhe irrelevante. O critério correto não é “usar por usar”, mas reconhecer que praticamente todo projeto de software possui áreas, tarefas ou regras que se beneficiam de especialização contextual. Quando nenhuma skill é mapeada, o mais provável não é que o projeto seja simples demais, e sim que suas oportunidades de especialização ainda não foram identificadas.

Mapear skills significa olhar para o projeto e perguntar quais capacidades especializadas fazem sentido naquele contexto específico. Essa análise não parte da ferramenta, mas do próprio software: tipo de sistema, natureza das tarefas, recorrência de decisões e necessidade de instruções que não devem ocupar contexto permanente. O objetivo do mapeamento é transformar a percepção difusa de “talvez aqui caiba uma skill” em um critério explícito para decidir onde a IA deve operar com apoio especializado.

Um racional útil para descobrir skills começa pela classificação do tipo de software em desenvolvimento. Sistemas diferentes concentram necessidades diferentes de orientação, e isso altera quais especializações devem existir. Em vez de tentar inventar skills de forma abstrata, o caminho mais sólido é partir da estrutura e do perfil do projeto para identificar onde a IA precisa de contexto adicional sob demanda.
